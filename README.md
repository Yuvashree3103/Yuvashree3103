## The Build Loop

> The part of my work that isn't on a resume: how I get from "something is wrong"
> to "something is running."

```text
   PROBLEM ──► DATA ──► PATTERN ──► DESIGN ──► BUILD ──► MEASURE ──┐
      ▲                                                            │
      │                                                            │
      └──────────────────────  I T E R A T E  ◄────────────────────┘
```

| Stage | What this actually means in my work |
| :-- | :-- |
| **Problem** | Start from who is losing time or missing something, not from the model. |
| **Data** | Find what exists, what's missing, and what the columns really mean. |
| **Pattern** | Explore before assuming — the signal decides the technique, not the reverse. |
| **Design** | Choose the architecture: rules, model, dashboard, or all three. |
| **Build** | Ship it as something usable — an app, an API, a dashboard. Not a notebook. |
| **Measure** | Check it against the original problem, not against training accuracy. |
| **Iterate** | Tighten the weakest stage and run the loop again. |
